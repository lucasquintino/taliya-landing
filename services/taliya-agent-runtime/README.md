# Taliya Agent Runtime

Python agent runtime for Taliya commercial conversations.

This service is the official runtime for the first production agent key, `taliya_commercial`. It follows the `openai/openai-cs-agents-demo` structure: explicit agents, model-callable tools, guardrails, typed context, handoffs, runner events, and persisted memory. Next.js remains the widget and WhatsApp channel boundary.

## Local Development

```powershell
cd services/taliya-agent-runtime
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
$env:TALIYA_AGENT_RUNTIME_HMAC_SECRET = "dev-secret"
$env:TALIYA_AGENT_PROVIDER = "mock"
uvicorn app.main:app --reload --port 8088
```

## Real OpenAI Local Eval

The official quality gate for conversational behavior must use the real OpenAI provider, not `mock`.
The repo-level `.env.local` may provide `OPENAI_API_KEY`; the eval runner loads only the required keys and does not print secrets.

```powershell
npm run eval:agent-runtime:real-openai
```

By default, the eval forces:

- `TALIYA_AGENT_PROVIDER=openai`
- `TALIYA_AGENT_MODEL=gpt-5.4-mini` unless already configured
- in-memory runtime state, so local quality evals do not write to the configured database

To intentionally include database persistence in the real eval, run:

```powershell
$env:AGENT_RUNTIME_REAL_EVAL_USE_DATABASE = "1"
npm run eval:agent-runtime:real-openai
```

The eval posts commercial turns to `/v1/taliya-commercial/turn` and writes complete transcripts to `specs/011-taliya-commercial-agent-core-reset/eval-reports/agent-runtime-real-openai-latest.md`.

## Production Boundary

Production is expected to run this service on Railway and the existing Next.js app on Vercel.

## Runtime API

- `GET /healthz`
- `POST /v1/taliya-commercial/turn`
- `POST /v1/agent-runs` for legacy operational control only

`POST /v1/taliya-commercial/turn` is the active commercial turn endpoint for the Taliya widget and Taliya-owned WhatsApp paths. It requires HMAC headers generated by the Next.js channel adapter and, in production, invokes the Spec 012 action-first Agents SDK core.

`POST /v1/agent-runs` is quarantined for Taliya commercial turns. It rejects normal `taliya_commercial` messages with `legacy_commercial_runner_quarantined` and is retained only for zero-token operational `runtime_control` handoff pause/resume calls plus legacy rollback/reference context. It is not a production behavior or quality gate for the commercial agent.

## Future agent boundaries

Only `taliya_commercial` is enabled by this feature. The runtime reserves generic names for future work, including `taliya_configuration` and the disabled `studio_*` operation agents such as `studio_lead_capture`, `studio_scheduling`, `studio_reactivation`, `studio_billing`, `studio_support`, `studio_retention`, and `studio_reporting`.

Those future keys are contract placeholders only. This service must reject them until a separate spec implements tenant scope, permissions, tools, evals, and production rollout for each family.
