# Contract Schema Map: Spec 011 Taliya Commercial Core Reset

Status: binding implementation map for `T011-023`.

This file is not a docs-only source. It is the implementation address book for
preserved behavior. Every preserved contract must land in at least one concrete
home: `schema`, `context`, `prompt`, `validator`, `renderer`, `projection`,
`trace`, or `eval`.

Core rule: no commercial deterministic routing. A commercial bug must be fixed
through regression case -> schema/context/prompt/validator/eval -> implementation,
not by adding another branch to `runner.py`, a template-first selector, or any
equivalent hidden conversation brain.

## Schema Coverage Snapshot

The current minimal core schema homes are:

- `TurnContext`: typed inbound turn, channel, facts, product knowledge, compact memory, recent transcript, diagnostic/waitlist/demo/handoff state, and Sales Inbox inputs.
- `ConductorDecision`: versioned structured JSON for route, role, state transition, intents, direct-question policy, facts, numeric grounding, diagnostic/demo/waitlist/handoff decisions, render plan, policy checks, confidence, and repair hints.
- `NumericInterpretation`: separates `plan_price`, `student_count`, `phone`, `date_time`, and `unknown_number`.
- `DiagnosticLedgerItem` and `DiagnosticDecision`: preserve mandatory diagnostic keys and next-step/final diagnostic decision shape.
- `TemplateVariableValue`, `RenderPlan`, and `OutboxPlan`: make templates a validated rendering/delivery layer instead of a hidden response generator.
- `ValidatorResult` and `RepairResult`: persist validation failures, repair attempt count, disposition, and one-repair-loop evidence.
- `TraceRecord`: mandatory turn trace with input, decision JSON, validators, repair, render plan, final rendered messages, model usage, runtime diff, delivery events, and Sales Inbox projection.
- `SalesInboxProjection`: projected operator state, identity, diagnostic/waitlist/handoff status, summary, and case-specific fields.

## Known Gaps

This map closes `T011-023`; it does not pretend the full implementation is done.

- Validators, renderer, conductor, persistence, delivery, and Sales Inbox projection implementation are still future stages.
- `runner.py` must not be promoted as the new commercial brain while these homes are being implemented.
